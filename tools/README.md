# Windows 服务器接入指南

本目录下的脚本用于把一台 Windows 服务器配置成可被「服务器监控台」采集的目标机。

**先看结论：优先用 SSH 路线。**

---

## 两条路线对比

| | **SSH**（推荐） | WMI（备用） |
|---|---|---|
| 目标机需要开放的端口 | **22 一个** | 135 + RPC 动态端口（49152-65535） |
| 采集账号所需权限 | `Performance Monitor Users` | `Administrators` |
| 需要的额外系统改动 | **无** | 要关 UAC 远程令牌筛选 |
| 受安全基线影响 | 几乎不受 | 容易被 DCOM/加固策略拦 |
| 命令在哪执行 | 目标机**本地** | 走远程 DCOM |
| 需要安装 | OpenSSH Server（本目录已附带） | 无 |

**为什么 SSH 更稳**：SSH 通道执行的是目标机**本地**命令，所以远程 DCOM 权限、UAC 令牌降权、RPC 动态端口这一整条容易出问题的链路全都不经过。WMI 路线卡住过很多次，绝大多数情况都是这条链路上的某一环。

---

## 路线一：SSH（推荐）

### 目标机操作

1. **把整个 `tools` 目录拷到服务器**。其中 `OpenSSH-Win64` 需要自行下载（见下方「关于 OpenSSH 版本」），其余文件仓库里都有。

2. 右键 `setup-ssh-target.cmd` → **以管理员身份运行**。

3. 看到 `Done` 就完成了。

脚本会自动做四件事：

| 步骤 | 内容 |
|---|---|
| 1 | 创建采集账号 `monitor`（口令运行时输入，直接回车则用预设值，见下），密码永不过期，加入 `Performance Monitor Users` |
| 2 | 把 `OpenSSH-Win64` 安装到 `C:\Program Files\OpenSSH` 并注册服务 |
| 3 | 启动 `sshd`、设为自动启动、放行防火墙 TCP 22 |
| 4 | 自检：确认端口在监听、账号在正确组里 |

> 要改账号名，编辑脚本开头的 `ACCOUNT` 一行。

#### 关于默认口令

脚本运行时会提示输入口令，**提示里直接写出默认口令是什么**，
**直接回车就用开头预设的 `set "DEFPASS=Srv@2026#Lan"`**。所以无人值守场景也不必先改脚本——一路回车即可。

> ⚠ **本仓库是公开的，写死在这里的口令等同于对外公开** —— 任何能看到这个仓库的人，
> 都能用 `monitor` + 这个口令登录所有跑过脚本的机器。正式环境**务必改掉**。

| 想要的效果 | 怎么改 |
|---|---|
| 换一个自己的口令 | 运行时手动输入；或直接编辑 `DEFPASS` 那一行 |
| 每台机器用不同口令 | 把脚本复制多份，每份改一行 |
| 彻底禁掉这个默认值 | 把那一行改成 `set "DEFPASS="`（清空）——此后必须手动输入，否则脚本报错退出 |

用到预设值时，脚本会在开头打印警告框，并在**结尾回显凭据时再提醒一次**。

**配置完成时脚本会把实际生效的账号和口令回显出来**，直接照抄进监控端即可：

```
  5. 用户名   ：monitor
  6. 口令     ：Srv@2026#Lan
```

> 回显用的是 `for /f` 而不是直接 `echo %PASSWD%`——口令里带 `&`、`|`、`<`、`>`
> 时，直接 echo 会被 `cmd` 当成元字符拆开（实测 `Ab#3&xY` 只回显前半截，
> 后半截还会被当成命令执行）。改这段的时候别改回直接 echo。

#### 改脚本时注意编码

`setup-ssh-target.cmd` 是 **GBK（cp936）** 编码的。

**改完请按「ANSI / GBK」保存，不要存成 UTF-8**——UTF-8 的中文尾字节会撞上
`&`、`|` 等元字符，注释行会被当成命令执行（实测踩过）。

（`setup-wmi-target.cmd` 目前仍是英文 / ASCII 输出，没有这个问题。）

### 监控端配置

添加服务器，按下表填：

| 字段 | 值 |
|---|---|
| 内网 IP | 服务器的内网 IP |
| 系统类型 | **Windows** |
| 采集通道 | **SSH** |
| 端口 | `0`（默认 22） |
| 用户名 | `monitor`（配置完成时回显的那个） |
| 口令 | 配置完成时回显的那个 |

点「测试连接」。

### 关于 OpenSSH 版本

Windows Server 2012 R2 **没有内置 OpenSSH**（`Add-WindowsCapability` 那条路只有 Server 2019+ 才有），必须手工部署。

**本仓库不包含 OpenSSH 二进制**（11MB 第三方发行包，不适合放进 git）。使用前请自行下载：

1. 打开 <https://github.com/PowerShell/Win32-OpenSSH/releases>
2. 下载 `OpenSSH-Win64.zip`
3. 解压后把文件夹**重命名为 `OpenSSH-Win64`**，放到本 `tools` 目录下

目录结构应该是：

```
tools/
├── setup-ssh-target.cmd
├── OpenSSH-Win64/          ← 解压到这里
│   ├── sshd.exe
│   ├── install-sshd.ps1
│   └── ...
```

> **版本选择**：推荐 **9.x 稳定版**（实测 9.5p1 可用）。9.x 是 2012 R2 上验证过的区间，**不要用 8.x 以下的旧版**，旧版在 2012 R2 上有兼容问题。
>
> `setup-ssh-target.cmd` 会检查这个目录是否存在，找不到会跳过安装并给出提示。

## 路线二：WMI（备用）

只有在**无法安装 OpenSSH** 时才走这条。

### 目标机操作

右键 `setup-wmi-target.cmd` → **以管理员身份运行**。

它会：

1. 放行 WMI 防火墙（135 + RPC 动态端口）
2. **关闭 UAC 远程令牌筛选**（`LocalAccountTokenFilterPolicy=1`）——不做这步，本地账号远程连接会被降权，WMI 必然报「拒绝访问」
3. 创建采集账号并加入 `Administrators` 和 `Performance Monitor Users`
4. 自检

### 监控端配置

| 字段 | 值 |
|---|---|
| 系统类型 | **Windows** |
| 采集通道 | **WMI**（或「自动」） |
| 用户名 / 口令 | `monitor` / 运行脚本时输入的那个 |

### 卡住了怎么办

运行 `check-wmi-access.cmd monitor`，它会把 12 项相关配置一次性打印出来：

```
check-wmi-access.cmd monitor
```

重点看第 **[5] DCOM 权限**和第 **[3] ForceGuest**。把输出发出来就能定位。

## 本目录文件说明

| 文件 | 用途 |
|---|---|
| `setup-ssh-target.cmd` | **配置 SSH 采集**（推荐路线，中文输出，GBK 编码） |
| `setup-wmi-target.cmd` | 配置 WMI 采集（备用路线，英文输出） |
| `check-wmi-access.cmd` | WMI 连不上时的诊断工具 |
| `OpenSSH-Win64/` | OpenSSH for Windows 二进制，SSH 路线需要（**需自行下载**，未随仓库分发） |

> 本目录下的脚本都是拷到**目标机**上、以管理员身份运行的。
> 在**开发机**上用的构建/图标脚本不在这里，都在仓库的 `build\` 目录下：
> `build\build.cmd` 一键构建（见「快速开始」），`build\make-icon.ps1` 生成程序图标。

> `cmd.exe` 错误解析——中文字符的 UTF-8 尾字节会撞上 `&`、`|` 等元字符，导致注释行
> 被当成命令执行（实测确认）。英文输出在任何语言系统上都正确。
>
> `setup-ssh-target.cmd` 已经汉化，走的是另一条路：存成 **GBK（cp936）** 而不是 UTF-8，
> 让文件编码和 `cmd.exe` 的代码页一致。改它的时候请保持 GBK 编码。

## 安全建议

### 1. 改掉默认口令

`setup-ssh-target.cmd` **预设了默认口令**（开头的 `DEFPASS` 一行），运行时直接回车即可用，代价是这个口令随仓库一起公开。改法见上方「关于默认口令」一节。

- **正式环境部署前先改掉它**：运行时手动输入一个，或把脚本里的 `DEFPASS` 改掉
- `setup-wmi-target.cmd` 仍然不预设口令，运行时提示输入
- 选口令时注意目标机的密码策略，以及避开 CMD 的特殊字符（见下方「密码策略」一节）

### 2. 考虑把账号移出管理员组

**走 SSH 路线时 `monitor` 不需要管理员权限**，`Performance Monitor Users` 就够读全部指标（命令是本地执行的）。脚本默认仍然把它加进管理员组，是为了兼容 WMI 路线。

确认 SSH 采集正常（CPU 显示真实百分比而非 0）之后，可以降权：

```cmd
net localgroup Administrators monitor /delete
```

然后回监控端点一次「测试连接」验证。**如果 CPU 变成 0 或报错，加回来即可**：

```cmd
net localgroup Administrators monitor /add
```

> 注意：`Performance Monitor Users` 这一组**不能删**。少了它的症状很隐蔽——内存和磁盘都正常，**只有 CPU 恒为 0**。

### 3. 关于主机密钥

监控程序**不校验 SSH 主机密钥**（SSH.NET 的默认行为）。这意味着理论上存在中间人风险。内网环境可接受，但如果你的环境有更高要求，需要自行评估。

### 4. 密码策略

如果目标机开了密码复杂性要求，注意 Windows 的规则是「**不能包含用户名或其连续 3 位以上片段**」。账号名是 `monitor`，所以 `Monitor@2026` 这类写法会被**直接拒绝**。

通过脚本设置口令时，避开 `%`、`"`、`^` 这三个字符（CMD 解析问题）；`&`、`|`、`<`、`>` 在引号内是安全的。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `'LC_ALL' 不是内部或外部命令` | 系统类型选成了 Linux | 编辑服务器 → 系统类型改 **Windows** |
| `远程命令返回码 1` + 一堆乱码 | 同上，或用了旧版 exe | 改系统类型；确保 exe 是最新的 |
| CPU 恒为 0，内存磁盘正常 | 账号不在 `Performance Monitor Users` 组 | 重新运行配置脚本 |
| `连接超时` | 端口不通 | 确认 sshd 在跑、防火墙放行 22 |
| `认证失败` | 口令不对 | 用脚本重设口令后再试 |
| 采集到的系统名称是乱码 | 旧版 exe（编码问题） | 换最新 exe，已修 |
