# 服务器监控台

一个 Windows 桌面程序，用于实时监控内网服务器的 **CPU / 内存 / 磁盘** 用量，
并按天沉淀统计数据，供日常运维盘点使用。

- **运行环境**：Windows Server 2012 R2 及以上（已针对 2012 R2 专门适配，零依赖安装）
- **被监控目标**：Linux（SSH）与 Windows（WMI / WinRM / SSH）
- **界面**：深色 / 浅色双主题，仪表盘式布局

![总览](docs/screenshot-overview.png)

> 只想快点用起来？直接看 **[使用手册](docs/使用手册.md)**。本文件重点讲设计与取舍。

## 一、快速开始

### 1. 构建

在**装有 .NET SDK 的机器**上（开发机）执行：

```cmd
build\build.cmd
```

或者手工执行：

```cmd
dotnet build src\ServerMonitor\ServerMonitor.csproj -c Release
```

产物在 `build\Release\net45\`，**只有一个 `ServerMonitor.exe`**
（外加一个仅用于排查崩溃的 `ServerMonitor.pdb`，部署时不需要）。

输出位置由项目自己决定（`ServerMonitor.csproj` 的 `OutputPath` 与
`Directory.Build.props` 的 `BaseIntermediateOutputPath`），所以上面两种构建方式落在
同一个地方；`src\` 下只有源码，编译产物和中间文件一律在 `build\` 里。

Release 编译结束后会跑一步「合并」：把 `Newtonsoft.Json` 与 `Renci.SshNet`
的 IL 直接并进 exe，并删掉散落的 dll，所以拷一个文件就能跑。合并只做 IL 层面的
合并，不是把 dll 压缩塞进去再运行期解包，因此启动不变慢、也不会被杀软拦。
Debug 配置不做合并，仍然是 exe + dll，便于调试。

### 2. 部署到服务器

把 `ServerMonitor.exe` 拷到目标服务器任意目录（例如 `D:\ServerMonitor\`），
双击即可，就这一个文件：

```
ServerMonitor.exe
```

> **不需要安装任何运行时。** Windows Server 2012 R2 自带 .NET Framework 4.5.1，
> 程序正是针对 net45 编译的。也不需要安装 Python、Node.js 或浏览器内核。

### 3. 添加服务器

打开程序 → 左侧「服务器」→「添加服务器」，填写：

| 字段 | 说明 |
|---|---|
| 内网 IP 或主机名 | 例如 `192.168.1.10`。建议直接填 IP，避免 DNS 解析问题 |
| 系统类型 | `Linux` 或 `Windows`，决定默认走哪条采集通道 |
| 采集通道 | 一般保持「自动」即可，特殊情况下手工指定（见下文） |
| 端口 | 留 `0` 表示用默认端口（SSH=22，WinRM=5985） |
| 用户名 / 口令 | 用于登录目标机采集 |
| 分组 | 可选，用于总览页筛选 |

保存前建议先点「**测试连接**」，能立刻看到成功或具体的失败原因。

## 二、目标服务器需要满足的条件

### Linux（SSH 通道）

- 目标机已启动 `sshd`，并允许**口令登录**（`PasswordAuthentication yes`）
- 默认 22 端口，或自行指定
- 采集账号无需 root，普通账号即可读取 `/proc` 与执行 `df`
- 用到的命令都是 POSIX 基础工具（`grep` / `cut` / `df` / `hostname` / `uname` / `getconf`），
  在 CentOS 6 这类老系统上同样可用

### Windows —— 推荐：SSH 通道

**优先用这条。** 目标机装 OpenSSH Server，程序通过 SSH 在目标机**本地**执行命令，
因此完全绕开远程 DCOM 权限、UAC 令牌降权、RPC 动态端口这一整条容易出问题的链路，
而且只需要开放 22 一个端口。

配置步骤、脚本用法、常见问题全部写在 **[`tools/README.md`](tools/README.md)**，
本目录下附带 `tools/OpenSSH-Win64`（OpenSSH for Windows 9.5p1，2012 R2 可用）。

> 下面的 WMI / WinRM 是**备用路线**，只在无法安装 OpenSSH 时使用。

### Windows —— 方式 A：WMI（备用）

- 采集账号需在目标机的**管理员组**内
- 目标机防火墙放行 WMI：**135 端口 + RPC 动态端口**，或直接放行 `Windows Management Instrumentation` 规则组
- 用户名可以只填 `Administrator`，程序会自动补成 `.\Administrator`（本地账号格式）

> ⚠️ **用本地账号从远程连接时，必须关掉 UAC 远程令牌筛选。**
>
> 从 Vista / Server 2008 起，Windows 有一条默认行为：**用本地账号（非域账号）
> 从另一台机器连接时，即使该账号在管理员组里，系统也会把管理员权限从令牌中剥掉**。
> 症状是：目标机上所有检查都正常（账号在 Administrators 里、密码正确、防火墙已放行），
> 但远程 WMI 始终报「拒绝访问」。
>
> 在**目标机**上以管理员身份执行一次即可（无需重启，下次连接生效）：
>
> ```cmd
> reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" /v LocalAccountTokenFilterPolicy /t REG_DWORD /d 1 /f
> ```
>
> `tools\setup-wmi-target.cmd` 已经包含这一步。
>
> 代价：这会让本地账号在远程拥有完整管理员权限。因此**务必使用专用的监控账号**
> （脚本创建的 `monitor` 就是），不要拿日常管理账号来做。
> 如果目标机在域内，**改用域账号可以完全避免这个问题**，不必改注册表。

> ⚠️ **监控本机时用户名和口令必须留空。** WMI 和 WinRM 都有一条硬性限制：
> **不允许对本机连接指定凭证**，填了会直接失败（报错可能是
> `0x80041064 用户凭据不能用于本地连接`，也可能是看起来毫不相关的
> 「**没有足够的内存继续执行程序**」——后者与内存无关，是 WMI 出了名的误导性报错）。
> 要监控别的服务器，请在地址里填**那台机器的内网 IP**，不要填 `127.0.0.1`。

**一键配置**：在目标机上以**管理员身份**运行一次即可：

```cmd
:: 右键「以管理员身份运行」，运行时会提示输入采集账号的口令
tools\setup-wmi-target.cmd
```

> 它刻意只用 CMD、不依赖 PowerShell——不受执行策略限制，也没有脚本编码问题。输出只用英文，
> 原因是 UTF-8 编码的 `.cmd` 会被 `cmd.exe` 错误解析：中文字符的 UTF-8 尾字节会撞上
> `&`、`|` 等元字符，导致注释行被当成命令执行（实测确认）。英文输出在任何语言系统上都正确。

它会放行防火墙、建采集账号、加入 `Administrators` 与 `Performance Monitor Users` 组，
并做一次自检。脚本只使用 PowerShell 2.0 就有的能力，因此
**Windows Server 2008 R2 ~ 2022 全系可用**（刻意没用 `Get-LocalUser` 等 cmdlet，
它们来自 LocalAccounts 模块，只有 PowerShell 5.0+ 才有，Server 2012 R2 自带的 4.0 里没有）。

### Windows —— 方式 B：WinRM（目标关闭了 WMI 时使用）

- 目标机执行过 `Enable-PSRemoting -Force`，且 WinRM 服务在运行
- 目标机 PowerShell 需为 3.0 及以上（Windows Server 2012 R2 自带 4.0，满足）
- **工作组环境**（非域）下还需在**运行本程序的机器**上，以管理员身份执行一次：

  ```cmd
  winrm set winrm/config/client @{TrustedHosts="192.168.1.10"}
  ```

  多个地址用英文逗号分隔。程序不会自动修改系统配置，只会在界面上提示这条命令。

## 三、功能说明

### 总览

- 顶部 7 项概览：服务器总数、在线数、偏高数、告警数、平均 CPU / 内存 / 磁盘
- 每台服务器一张卡片：三只环形仪表 + 状态文字标签 + 内存与容量明细 + 磁盘列表
  （快写满的分区会在用量条下方标注“按当前增速约 N 天后写满”）
- 支持按名称 / 地址 / 分组搜索，支持「只看异常」过滤
- 卡片上**右键**可编辑、测试连接、停用启用、删除

### 服务器管理

表格化列出全部服务器，含实时指标、更新时间与离线原因，可直接操作。

### 历史统计

这是「每天统计」的主要入口：

- 按日期查看每台服务器的**在线率、CPU 均值/峰值、内存均值/峰值、磁盘均值/峰值**
- 支持导出当日 CSV（带 BOM，Excel 打开中文不乱码）
- 下方为当日走势图，可切换服务器，鼠标悬停显示十字准线与数值

![历史统计](docs/screenshot-history.png)

### 诊断日志

程序运行时会把关键事件写入日志文件，出问题时这是第一手排查资料。

左侧「诊断日志」页可以实时查看，也可以按级别筛选、导出成文件发给他人。

| 级别 | 记录内容 |
|---|---|
| `error` | 仅严重错误（程序自身缺陷、数据损坏） |
| `warn` | 错误 + 采集失败、认证失败等警告 |
| `info` | 再加上启动退出、服务器增删改等一般操作（**默认**） |
| `debug` | 再加上每台服务器的采集耗时与结果 |
| `trace` | 全部日志，含远程命令原文与原始输出 |

日志按天存放在 `data\logs\` 下，默认保留 14 天（可在设置页调整）。

几个刻意的设计：

- **异常堆栈**：`error` 级别无条件输出（那是程序缺陷，堆栈是必需信息）；其它级别只在 `debug` 及以上输出，否则持续性的采集失败会用重复堆栈把日志冲垮
- **重复失败抑制**：同一台服务器连续报同一个错时，只写一行摘要并标注"与前次相同，堆栈已省略"，错误内容变了才重新输出完整堆栈
- **口令不落盘**：涉及口令的日志只记录长度（如 `口令=已设置(12位)` 或 `口令=空(0)`），既能判断"有没有传进去"，又不会把凭据写进文件

> 排查完问题后记得把级别调回 `info`——`trace` 级别会记录每条远程命令的原文和输出，日志增长很快。

### 设置

刷新间隔、并发采集数、告警阈值、数据保留天数、日志级别、主题切换、数据目录、
关闭主窗口时的行为（每次询问 / 后台运行 / 直接退出）。

### 后台运行（关闭窗口时）

监控程序的价值在于"一直看着"，所以点标题栏的关闭按钮时默认会先问一次：

| 选择 | 结果 |
|---|---|
| 取消 | 什么都不做，窗口留着 |
| 后台运行 | 窗口隐藏到通知区域，**采集、阈值告警与 Webhook 推送照常进行** |
| 关闭 | 退出程序，采集停止 |

勾上「记住我的选择」之后不再询问，选择记在 `settings.json` 的 `CloseAction` 里，
随时可以在设置页「窗口与后台运行」一节改回「每次询问」。

窗口隐藏后，通知区域的图标就是唯一入口（悬停有提示文字）：

| 操作 | 结果 |
|---|---|
| 双击图标 | 回到主界面（回来前会检查窗口是否还落在可见区域内） |
| 右键 → 显示主界面 | 同上 |
| 右键 → 立即刷新 | 立刻采集一轮，不必打开窗口（与 F5 同一条路） |
| 右键 → 退出 | 退出程序，日志以「程序已退出」收尾 |

两个刻意的处理：

- **托盘图标建不出来时不硬藏窗口**。若通知区域不可用，关窗会退化成"最小化到任务栏"
  并记一条 `warn` —— 否则用户会以为程序已经关了，其实它还在后台跑。
- **关机 / 注销与关窗区别对待**。系统关机时程序直接跟着退出，不弹询问框——
  拦下来会变成"此程序阻止关机"。

程序带**单实例**检查：重复启动不会再开一个进程，而是把已经在跑的那个窗口叫出来。
数据目录不同的两份便携副本（各写各的 `data\`）互不影响，可以同时运行。

## 四、数据存储

所有数据存放在程序目录下的 `data\` 子目录（用本仓库的 `build\build.cmd` 构建时，
程序目录就是 `build\Release\net45\`）：

```
data\
├── servers.json                    服务器配置（口令为 DPAPI 密文）
├── settings.json                   全局设置
├── summary.json                    每日汇总（永久保留）
└── history\
    ├── 2026-09-17.json             当日原始采样，每分钟一条
    └── ...
```

- **原始采样**：每分钟每台服务器记录一条，用于绘制全天走势；超过保留天数（默认 30 天）自动清理
- **每日汇总**：按 服务器 × 日期 记录均值与峰值，体积很小且**永久保留**，
  因此即使原始数据被清理，长期统计也不会丢失
- 若程序目录不可写（例如装在 `Program Files` 下），会自动改用
  `%LOCALAPPDATA%\ServerMonitor\`，启动时无需干预

### 口令安全

口令使用 **Windows DPAPI（当前用户范围）** 加密后写入 `servers.json`，不会明文落盘。
需要注意的副作用：

- 把 `data` 目录拷到**另一台机器**或**另一个 Windows 账户**下，口令无法解密，
  需要重新填写（其余配置与历史数据不受影响）
- 这是有意的设计：配置文件被拷走也无法还原口令

## 五、设计说明

### 为什么锁定 .NET Framework 4.5

目标环境是 Windows Server 2012 R2，它自带 .NET Framework 4.5.1。
锁定 net45 后程序可以**拷贝即用、零安装**——不用装 Python、Node.js 或任何运行时，
这在很多内网服务器上是硬性要求。

代价是不能使用 .NET 4.6.2+ 的新 API（例如 `FormattedText` 的 `pixelsPerDip` 重载），
代码里已在相应位置标注。若目标环境均为较新的系统，可把
`ServerMonitor.csproj` 里的 `TargetFramework` 改为 `net462` 或 `net48` 重新编译。

### 告警等级为什么只有三档

界面刻意只区分 **正常 / 偏高 / 告警** 三档，而不是常见的四档。

原因是配色经过色盲安全校验后发现：四档方案里「偏高（琥珀）」与「严重（橙）」
在正常视觉下的色差（OKLab ΔE 13.6）低于可辨识下限 15，即**不色盲的人也难以一眼区分**。
这会让仪表盘上"到底要不要处理"这个判断变得不可靠，所以直接收敛到三档。

三档方案（绿 `#0CA30C` / 琥珀 `#FAB219` / 红 `#D03B3B`）的分离度校验全部通过
（最差相邻对正常视觉 ΔE 27.6），且每一处状态色**都同时配有文字标签**，
不依赖颜色单独表意，色盲用户也能准确读取。

### 其他

- **不绘制阴影效果**。Windows Server 2012 R2 常常没有可用 GPU，WPF 会退回软件渲染，
  阴影在多卡片网格下开销明显。层次感改用「表面色阶 + 1px 发丝描边」实现。
- **图标全部是矢量几何**，没有使用图标字体。因为 `Segoe MDL2 Assets` 是 Windows 10 才引入的，
  在 2012 R2 上会显示成方框。
- **图表全部自绘**（环形仪表 / 条形计 / 折线图），不依赖任何第三方图表库。

## 六、常见问题

**连不上 Linux 服务器**

点「测试连接」看具体提示。常见原因：
- `目标端口不是 SSH 服务` —— 该端口上跑的不是 sshd
- `认证失败` —— 用户名或口令错误，或目标禁用了口令登录
- `连接超时` —— 内网不通，或被防火墙丢包

**连不上 Windows 服务器（WMI）**

- `WMI 拒绝访问` —— 账号不在管理员组，或 DCOM 权限不足
- `RPC 服务器不可用` —— 目标防火墙拦了 WMI，需放行 135 端口与动态端口；
  若无法调整防火墙，改用 **WinRM** 通道

**WinRM 报信任关系错误**

按上文在工作组环境下配置 `TrustedHosts` 即可。

**程序启动后窗口一闪就没了**

说明启动阶段抛了异常。程序会把未处理异常弹窗提示而不是直接退出；
若仍然秒退，请检查 `data\servers.json` 是否被手工改坏（删掉该文件会恢复默认）。

## 七、项目结构

```
ServerMonitor/
├── src/ServerMonitor/
│   ├── Models/          数据模型（配置、快照、采样、设置）
│   ├── Services/        采集与存储
│   │   ├── SshCollector.cs      Linux：一次 SSH 往返取全部指标
│   │   ├── WmiCollector.cs      Windows：WMI/DCOM，CPU 三级降级策略
│   │   ├── WinRmCollector.cs    Windows：PowerShell 远程
│   │   ├── MonitorEngine.cs     定时并发调度
│   │   ├── ConfigStore.cs       配置读写 + DPAPI 口令加密
│   │   └── HistoryStore.cs      日采样 + 日汇总
│   ├── Controls/        自绘控件（仪表、条形计、折线图）
│   ├── ViewModels/      MVVM
│   ├── Views/           四个页面 + 三个对话框 + 通知区域图标（TrayIcon.cs）
│   └── Themes/          设计令牌（深浅两套）+ 控件样式 + 矢量图标
├── Directory.Build.props 构建输出位置：产物与中间文件都落在 build\ 里
├── build/               构建脚本与产物：build.cmd 一键构建（见「快速开始」）、
│                        make-icon.ps1 生成程序图标；
│                        Release\ 是编译产物，obj\ 是中间文件，都不入库
├── tools/               目标机配置脚本（见 tools/README.md）
└── docs/                截图与使用手册
```
